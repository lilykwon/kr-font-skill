# Font License Audit

폰트 라이선스 문제는 "무료인 줄 알았는데 개인용만 무료였다", "웹은 되지만 로고는 안 됐다" 같은 데서 생긴다. 이 스킬은 프로젝트나 사이트에서 쓰인 폰트를 빠짐없이 찾고, 실제 용도와 라이선스 원문을 대조해 위험을 알려준다.

원칙:
- 점검만 한다. 폰트 파일을 지우거나 코드를 바꾸는 건 사용자가 보고서를 보고 요청했을 때만 한다
- 추측해서 "괜찮다"고 하지 않는다. 원문을 못 찾으면 "확인 필요"다
- 법률 자문이 아니라는 점을 보고서 맨 위에 한 줄로 적는다

## 0. 범위와 용도 확인

- 대상: 로컬 프로젝트 폴더, 배포된 웹사이트 URL, 또는 둘 다
- 용도 파악 (없으면 코드와 사이트에서 추정하고 밝힌다): 웹사이트, 앱 번들(iOS/Android/데스크톱), 로고/BI/CI, 패키지/상품, 영상, 인쇄, 전자책, 게임
- 사업자 규모가 조건인 라이선스도 있다 (예: 5인 미만 기업만 무료). 해당 폰트가 나오면 직원 수를 묻는다

## 1. 폰트 찾기

### 프로젝트 폴더
- 폰트 파일: `*.ttf *.otf *.woff *.woff2 *.ttc *.eot` (node_modules, 빌드 결과물 포함해서 찾되, 출처를 구분해 기록)
- 코드 안의 참조: `@font-face`, `font-family`, `@import`, `<link>`(fonts.googleapis.com, cdn.jsdelivr.net/gh/projectnoonnu, api.fontshare.com, use.typekit.net 등), `next/font`, Tailwind `fontFamily`, CSS-in-JS, iOS `Info.plist`의 `UIAppFonts`, Android `res/font`, Flutter `pubspec.yaml`의 fonts, Unity/게임 엔진 에셋
- 디자인 파일이 있으면 언급만 한다: Figma, AI, PSD 안의 폰트는 이 스킬로 완전히 못 찾는다고 알린다

### 웹사이트
- HTML과 연결된 CSS를 가져와 `@font-face`와 폰트 URL을 모은다. 브라우저 도구가 있으면 네트워크 요청에서 폰트 파일을 찾는 게 더 정확하다
- 로고가 텍스트가 아니라 이미지/SVG여도 어떤 폰트로 만들었는지는 여기서 알 수 없다. 사용자에게 물어본다

## 2. 폰트 신원 확인

파일이 있으면 fontTools로 name 테이블을 읽는다 (`pip install fonttools`, 읽기만 하고 실행은 폰트 폴더 밖의 스크립트로):
- nameID 1/16 패밀리명, 0 Copyright, 7 Trademark, 8 제작사, 9 디자이너, 13 라이선스 설명, 14 라이선스 URL
- OS/2 테이블의 `fsType`(임베딩 허용 플래그)와 vendor ID
- 폰트 파일 옆에 LICENSE, OFL.txt, 사용설명서가 있는지

그다음 라이선스 원문을 찾는다. 우선순위:
1. 패키지 안의 라이선스 파일
2. 공식 배포처의 라이선스 페이지 (nameID 14 URL, 제작사 사이트)
3. 눈누, 산돌구름 무료폰트, 공유마당, Google Fonts 같은 집계 사이트의 요약표 (보조 자료로만 쓴다. 집계 사이트 표와 원문이 다르면 원문을 따르고 차이를 기록한다)

## 3. 점검 항목

폰트마다 실제 용도와 원문을 대조한다. 자주 나오는 위험:

- **개인용 전용 폰트의 상업적 사용**: "Free for personal use", 데모 폰트, dafont/1001fonts 출처
- **용도 제한 위반**: BI/CI(로고, 상호, 상품명) 금지 폰트를 로고에 사용, 임베딩 금지/조건부 폰트를 웹이나 앱에 탑재, 포장 금지 폰트를 상품에 사용
- **수정 금지 위반**: 수정/포맷 변환 금지 폰트가 서브셋되거나 woff2로 변환돼 있음 (파일명에 subset, 글리프 수가 공식본보다 적음, 공식 배포본에 없는 포맷)
- **OFL 조건 누락**: Reserved Font Name이 있는 폰트를 수정하고도 원래 이름 사용, 앱/패키지 번들에 라이선스 텍스트 누락
- **출처표시 의무 누락**: 공공누리 제1유형, 기관/지자체 폰트처럼 출처 표기가 조건인데 사이트나 앱 어디에도 표기가 없음
- **사업자 조건 위반**: 인원, 매출, 업종 조건이 있는 폰트
- **시스템/앱 폰트의 재배포**: Apple SD Gothic Neo, 맑은 고딕, SF Pro, Segoe UI 같은 OS 폰트 파일을 웹에 올리거나 앱에 번들한 경우. 이들은 OS 라이선스로 제한되며 `local()`이나 시스템 폰트 스택으로 쓰는 건 문제가 아니다
- **유료 폰트**: 산돌, 윤디자인, 폰트릭스, Adobe Fonts, Monotype 등. 라이선스 증빙(구매 내역, 구독 계정)을 가지고 있는지 묻고, 웹/앱 임베딩은 보통 별도 라이선스가 필요하다는 점을 알린다. Adobe Fonts는 파일을 앱에 번들하거나 웹에 자체 호스팅할 수 없는 것이 일반적이다
- **출처 불명**: name 테이블의 제작사와 배포 경로가 맞지 않거나, 유료 폰트가 무료 경로로 들어온 흔적
- **라이선스 변경**: 무료 폰트도 약관이 바뀌는 경우가 있다. 원문을 확인한 날짜를 기록한다

## 4. 위험도 분류

- **높음**: 명백한 원문 위반 (개인용 폰트의 상업 사용, BI/CI 금지 폰트의 로고 사용, 임베딩 금지 폰트의 번들, 유료 폰트 무단 사용 의심)
- **중간**: 조건 누락 (출처표시 없음, OFL 라이선스 동봉 누락, RFN 이름 미변경, 수정 금지 폰트의 변환)
- **확인 필요**: 원문을 못 찾음, 용도 불명, 집계 사이트와 원문 불일치, 유료 라이선스 보유 여부 모름
- **문제 없음**: 원문을 확인했고 현재 용도가 모두 허용됨

## 5. 보고서

`FONT-AUDIT.md` 를 만든다 (사용자가 원하면 다른 형식으로):

1. 맨 위: 점검 날짜, 대상, 가정한 용도, "법률 자문 아님" 한 줄, 위험도별 개수 요약
2. 폰트별 표: 폰트명, 발견 위치(파일 경로와 줄 번호 또는 URL), 쓰이는 용도, 라이선스, 원문 URL, 위험도, 근거(원문의 해당 조항을 짧게 요약)
3. 위험도 높음과 중간 항목마다 구체적인 해결책:
   - 공식 웹폰트로 교체, 출처표시 문구 추가 위치, 라이선스 파일 동봉 방법
   - 로고 문제는 BI/CI 허용 폰트로 교체하거나 저작권자에게 문의
   - 비슷한 무료 대체 폰트가 필요하면 font-alternatives 스킬을 제안
   - 파일 최적화가 필요하면 korean-webfont-optimize 스킬을 제안
4. 확인 필요 항목은 사용자가 확인해야 할 것(구매 내역, 저작권자 문의 등)을 짧은 체크리스트로

보고서를 전달한 뒤, 사용자가 원하면 수정 작업을 진행한다. 파일 삭제는 항상 목록을 보여주고 확인받은 뒤에만 하고, 커밋도 물어본 뒤에만 한다.

## 마지막 점검

- 코드 참조와 파일 둘 다 찾았는가 (CDN으로만 불러오는 폰트, 빌드에만 있는 폰트를 놓치지 않았는가)
- 모든 판정에 원문 근거와 확인 날짜가 있는가
- 집계 사이트 표만 보고 판정한 항목이 없는가
- 어떤 파일도 사용자 확인 없이 수정하거나 지우지 않았는가
