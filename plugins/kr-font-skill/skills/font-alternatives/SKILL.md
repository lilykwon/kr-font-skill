# Font Alternatives

"이 느낌인데 무료로" 요청을 처리한다. 입력은 세 가지 중 하나다: 유료 폰트 이름, 글씨가 들어간 이미지, 또는 웹사이트 URL. 출력은 형태가 비슷하고 상업적 무료 사용이 가능한 폰트 후보와, 원본과 나란히 비교하는 보드다.

하지 않는 것:
- 유료 폰트를 무료로 받는 경로, 복제판, 리네임된 폰트, "무료 다운로드" 재업로드 사이트는 찾거나 안내하지 않는다
- 원본 폰트의 글리프를 트레이싱해서 새 폰트를 만드는 일은 돕지 않는다
- "똑같다"고 하지 않는다. 대체 폰트는 비슷한 것이고, 무엇이 다른지 항상 말한다

## 0. 입력 정리

- 어떤 용도인지 파악한다 (로고/BI, 웹, 앱, 패키지, 영상, 인쇄). 용도에 따라 허용되는 후보가 달라진다. 말하지 않으면 웹 + 로고로 가정하고 밝힌다
- 언어: 한글, 영문, 둘 다
- 얼마나 가까워야 하는지: "거의 같은 인상" 또는 "분위기만 비슷하게"

## 1. 원본 분석

### 폰트 이름을 받은 경우
- 제작사 공식 페이지나 판매 페이지를 찾아 분류, 웨이트, 디자인 의도를 확인한다. 공식 스페시먼 이미지가 있으면 본다
- 이름이 모호하면 (같은 이름의 다른 폰트) 어느 것인지 묻는다

### 이미지를 받은 경우
- 이미지를 직접 보고 형태를 관찰한다. 글자가 작거나 흐리면 확대해서 본다
- 기성 폰트가 아니라 손으로 그린 레터링이나 로고일 가능성을 항상 염두에 둔다. 그렇다면 그렇게 말하고 "가장 가까운 분위기의 폰트"를 찾는다
- 폰트를 특정해 내는 것은 확신이 있을 때만 한다. 불확실하면 "아마 OO 계열"처럼 말하고, 영문은 사용자에게 WhatTheFont나 Font Squirrel Matcherator 같은 식별 서비스를 써 볼 수 있다고 알려준다

### URL을 받은 경우
- CSS에서 실제 폰트 이름을 찾는다. 로고가 이미지면 이미지 분석으로 넘어간다

### 형태 특징 기록 (비교의 기준)
다음을 짧게 적는다. 말로 된 기준이 있어야 후보를 골라낼 수 있다.
- 한글: 분류(민부리/부리/손글씨/디스플레이), 네모틀인지 탈네모인지, 자폭(좋음/넓음), 중심선 높이, 받침 크기, 획 대비, 부리의 모양(붓맛/기하학적/없음), 획 끝(둥글음/각짐/빗금), 이응의 형태(원형/타원/꼭지 여부), 굵기
- 영문: 분류(세리프/산세리프 하위 양식: 지오메트릭, 그로테스크, 휴머니스트, 디돈, 슬랩 등), x-height, 자폭, 어퍼처(열림/닫힘), 특징 글자(a, g, R, Q, y의 모양), 대비, 터미널
- 인상: 형태 특징이 만드는 느낌을 한 줄로 (예: "타원 이응과 좁은 자폭이 날렵하고 도시적인 느낌")

## 2. 후보 찾기

font-research 스킬의 소스와 규칙을 그대로 따른다.
- 한글: 눈누, 공유마당 안심글꼴, 네이버 한글한글 아름답게, 산돌구름 무료 폰트, Google Fonts, GitHub 배포 폰트
- 영문: Google Fonts, Fontshare, Velvetyne, Collletttivo, The League of Moveable Type, uncut.wtf, Open Foundry
- 후보의 절반 이상은 이번에 실제로 카탈로그를 둘러보고 찾는다. 카테고리(명조, 고딕, 디자인체 등)와 1단계의 형태 키워드로 검색한다
- "OO 대체 폰트", "OO alternative" 같은 검색 결과는 신뢰하지 말고 출발점으로만 쓴다. 그런 목록은 복제판이나 개인용 폰트를 섞는 경우가 많다
- font-research의 AI 시그니처 금지 목록은 기본으로 피한다. 단, 원본이 그런 양식이고 그 폰트가 가장 가까운 대안이면 이유를 말하고 후보에 넣을 수 있다. 본문용 기본 폰트(Pretendard, Noto Sans KR, Inter 등)도 원본이 본문 폰트라면 정당한 후보다
- `~/.claude/font-research/history.md` 가 있으면 읽고, 이번 결과도 거기에 기록한다

후보는 3~8개. 각 후보에 대해:
- 원본과 비슷한 점 1줄, 다른 점 1줄 (1단계의 형태 항목으로 말한다)
- 유사도: 높음 / 중간 / 분위기만. 숫자 점수는 만들지 않는다
- 웨이트 수, 한글 지원 범위(2,350자인지 11,172자인지)

## 3. 라이선스 확인

- font-research의 라이선스 규칙을 따른다. 원문을 직접 확인하고, 사용자 용도별로 O / X / 확인 필요를 매긴다
- 사용자가 로고에 쓸 예정이면 BI/CI 허용 여부를 가장 먼저 본다. 허용되지 않는 후보는 빨간 표시를 달고 뒤로 보낸다
- 로고를 만들 때 폰트를 아웃라인으로 바꿔 변형할 계획이면, "수정 금지" 라이선스가 글자 변형에도 적용되는지 원문을 확인하고, 불분명하면 저작권자 문의를 권한다
- 전달 시 법률 자문이 아니라는 점을 한 줄로 알린다

## 4. 비교 보드

font-research 보드와 같은 방식으로 만들되, 원본과의 비교에 맞춘다.
- 파일: `fonts/alternatives-board.html` (인라인 위젯 도구가 있는 환경이면 위젯도 가능)
- 맨 위에 원본: 사용자가 준 이미지나 공식 스페시먼의 스크린샷, 또는 폰트 이름과 1단계 형태 요약. 유료 폰트 파일 자체를 보드에 임베딩하지 않는다
- 각 후보 카드: 원본 이미지에 나온 것과 같은 문구를 그 폰트로 렌더링, 비슷한 점과 다른 점, 유사도, 용도별 라이선스 배지, 공식 페이지 링크
- 상단 문구 입력창과 원본 이미지 옆에 후보를 겹쳐 보는 토글(투명도)을 넣으면 좋다
- 웹폰트 로딩과 스크린샷 대체 방식은 font-research의 미리보기 규칙을 따른다. 로딩에 실패한 카드는 실패했다고 표시하고, 다른 폰트로 렌더링된 걸 그 폰트인 척 보여주지 않는다
- 선택 복사 버튼으로 다음 단계에 넘긴다

## 5. 다음 단계

- 선택한 폰트는 font-research의 확보 단계(다운로드, LICENSES.md, CSS)로 넘긴다
- 기존 사이트의 유료 폰트를 교체하는 상황이면, 교체 후 줄바꿈과 레이아웃이 달라질 수 있다고 알리고, 필요하면 `size-adjust`로 메트릭을 맞추는 방법을 제안한다 (korean-webfont-optimize 스킬)
- 원본과 똑같아야 하는 상황(기존 브랜드 가이드 준수 등)이면 대체보다 원본 라이선스를 구매하는 게 맞다고 솔직하게 말한다

## 마지막 점검

- 복제판, 개인용 폰트, 무단 재배포 파일이 후보에 없는가
- 모든 후보에 "다른 점"을 솔직하게 적었는가
- 이미지 속 글씨를 특정 폰트로 단정한 경우, 그만한 근거가 있었는가
- 사용자 용도에서의 라이선스를 원문으로 확인했는가
- 보드를 실제로 열어 후보 폰트가 제대로 로드되는지 확인했는가
